Streaming Trading Data Platform

project_design.md scaffold

Turns live + historical NSE market data into real-time, feature-rich data the trade execution engine reads. Macro design only — nothing built yet. Phase 4.1 (Design & architecture) closed. Companion files: ROADMAP.md (process), STATUS.md (status).

⛔
Order path safe-halts. On uncertain state (stale signal, duplicate-order risk, missed fill, checkpoint failure) the system stops placing NEW orders and alerts. Existing positions are babysat, but no new risk is taken until cleared. No auto-recovery into placing orders.
⚡
OpenAlgo must be push-driven. The tens-of-ms tick→instruction budget excludes the broker REST call (~100–300ms). Hitting it requires OpenAlgo to be event/push-driven, not a polling KV reader. Mechanism (KV push vs change-log tail) is a deferred execution decision.

Purpose

Bring live + historical data together and compute features on the fly — instead of pre-baking Parquet. Today's chart tool only reads historical Parquet; this adds the live path.

Boundaries

  • In: full NSE (EQ, FO options/futures, index quotes)
  • Out: BSE, currency, commodity
  • Chart tool + alerts deferred to 4.7
  • Order placement in scope (→ broker → exchange)

Two-tier storage model

One live source of truth by day; a continuous, durable historical tier. Lake writes are continuous, not an EOD batch.

Live — Fluss log

Single source of truth during the day. Short retention; tiers out continuously.

Lake — Iceberg on S3

Cold/historical tier. Continuous tiering via table.datalake.freshness (~5–10 min). Read after EOD.

Old Parquet

One-time backfill into the Iceberg lake, then retired. Single history store going forward.

Data path (decided)

One live source of truth (Fluss log) + continuous lake tier (Iceberg on S3). Two Flink jobs split by responsibility.

Components

Ingestor new

Zerodha Kite WS → Fluss Java client → raw_table_1. Direct WS, single broker.

Flink: signal job

Ticks → features → stateful + CEP → instructions (KV) + feature tables (log). Exactly-once.

Flink: babysitter job

Reads fills + state → trim / re-entry / exit → KV. Position management.

Fill-capture new

Broker postback → Fills_table + KV lifecycle. Bypasses OpenAlgo.

Fluss

Bus + storage: raw, fills, feature logs, KV, + Iceberg/S3 lake tier.

Feature tables log

Append-only Fluss log (not KV). Each closed candle = one row; full history, replayable, tiers to lake.

OpenAlgo

Dumb executor. Reads KV, places orders. No strategy, no fills.

OpenObserve

Logs, metrics, traces across all components.

Docker

Runtime wrapper — runs everything in containers.

Lake tier

Iceberg on S3. Continuous tiering ~5–10 min. Old Parquet backfilled then retired.

raw_table_1 macro

One unified append-only log: trades + L1 BBO, split by tick_type. Describes any NSE instrument (EQ/FO/future/index). Schema deferred.

Key decisions (4.1 — closed)

●Fluss is both bus and storage; lake tier = remote durable store.
●Ingestion is direct broker WS → Fluss; OpenAlgo is consumer, not source.
●Strategy in Flink via stateful operators + CEP, split across 2 jobs.
●Fills captured independently; OpenAlgo never touches fills.
●Signal job consumes in-flight feature stream, not raw ticks / feature tables.
●Initial compute = candles only; 250+ features deferred to evolution.
●raw_table_1 = one unified log (TRADE | QUOTE), bucketed by instrument_token.
●OpenAlgo read-only on KV; all writes from Flink + fill-capture.

KV writer coordination — resolved

Trade_management_table keyed by order ID, written by 3 producers. Fluss partial-update merges per-column; column ownership removes the conflict.

Writer Owns (columns) Writes via
Signal job entry, exit, position_size, trimming Flink
Babysitter job re_entry, exit_override, trim_adj Flink
Fill-capture status, fill_qty, fill_price Fluss Java client
⚠
Caveat: Java-client writers (fill-capture) are not exactly-once by default — must be idempotent on retry. Column ownership makes re-sends safe.

NFRs

Throughput

Full NSE: ~5k–20k instruments, peak ~10k–50k ticks/sec. L1-only caps per-tick size.

Failure posture

Data path auto-recovers. Order path safe-halts — no new orders on uncertain state.

Latency

Tens of ms tick→instruction-emitted (excl. broker REST ~100–300ms). Implies OpenAlgo push-driven.

Observability scope

In scope (operational / SLA)

  • Infra health + SLA pipeline metrics
  • Open positions, fill counts, notional exposure
  • Per-order fill-vs-signal deviation

Out of scope (business)

  • P&L, win rate
  • Aggregated slippage cost
  • Strategy performance — revisit 4.7
