## Data-flow rule

Ranking executes inside the Signal Flink job. It does not read candidates back from Fluss and there is no separate Ranking checkpoint or deployment. The Signal job publishes immutable candidates, ranking audit records, and immutable instructions under one job boundary.

## Identity rule

`instruction_id`, `client_order_ref`, `broker_order_id`, `trade_context_id`, `position_id`, and `execution_attempt_id` are distinct. No requirement may use an overloaded `order_id` as a substitute for these identities.

## Guarantee rule

Exactly-once is permitted only where the pinned Flink/Fluss connector tests prove it. External broker calls, cross-table visibility, and independently submitted writes are at-least-once or uncertain until reconciled.

## Reading order

Read context first, then ingestion and storage, then compute/business logic/ranking, then Action Capture and Executor, and finally observability/runtime. Use the matching issue reports under `Issues_presents/` as audit history, not as an authority source.
