## What changed

1. **`code/01_platform/01_docker/docker-compose.yml`** — the `execution-gateway` service
   now maps `EXECUTION_ENABLED: ${EXECUTION_ENABLED:-false}`.
   - Why: `GatewayConfig.fromEnv` (`GatewayConfig.java:112`) reads `EXECUTION_ENABLED`
     with a fail-closed `"false"` default, but the service had no compose mapping — so
     even after the `.env` flip, `/v1/events` and `/control/approve` would keep
     returning 503 and the A2.4 emission leg could never pass live.
   - Safety: default `false` preserves the `.env.example:16` rule ("EXECUTION_ENABLED
     must remain false"); nothing changes until the operator explicitly flips `.env`.

2. **Plan Task A2** — A2.4 assert rescope to two tables (operator-approved Option A):
   `Order_Lifecycle` + `Order_Correlation` populated + `client_order_ref` echoed.
   `Execution_Attempts` is asserted in its own dispatcher-path test (the Java
   `DurableIntentDispatcher` writes attempts on the signal→gateway path; the sandbox
   harness posts directly to nautilus and does not traverse it). B7.5 durable-flag
   decision deferred.

## Compatibility note (COMPATIBLE_WITH_LIMITATION)

The limitation is deliberate and recorded: until B7.5 is approved, the direct-to-nautilus
sandbox path cannot populate `Execution_Attempts`. This is not a regression — the table's
writer was never on this path.
