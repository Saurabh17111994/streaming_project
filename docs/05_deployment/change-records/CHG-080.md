## 3. Gate-flow proof (the control question B6 must answer)

The order path must only reach `ENABLED` via the sanctioned single-operator path:

```
HALTED → RECONCILING → APPROVAL_PENDING → ENABLED
```

- **Only sanctioned path:** `gate::tests` (11) + executiongate lifecycle (20) = 31 green;
  no skip/regress, no unauthorized transition (CHG-070, B3).
- **Single-operator binding:** `saurabh` approval binds to an evidence hash + matching
  gate epoch; fencing means a stale epoch/fence token can never issue a bridge call
  (`invariant003_no_enabled_without_approval`, `control001/002`, `fence009/010/012`).
- **Fail-closed at boot:** every `LiveNodeRuntime`/factory path boots `HALTED`; no broker
  command flows before approval (B1 soak, B9 factory, `gate_was_halted_at_boot`).
- **Safety halt within 5 s:** instant `safety_halt()` → `HALTED` from any state, clears
  approval, requires re-approval; liveness sampled at 500 ms in `live_node_soak`
  (`control006_safety_halt_invalidates`, `clockwatch::tests::beyond_limit_halts`).
- **Crash exactly-once:** `kill -9` mid-order replays halts with ZERO duplicate broker
  calls (B2/CHG-063); epoch bump cannot fence an unresolved attempt — quarantine holds.
- **Honest boundary:** the compose E2E leg (Fluss bus → `healthz` flip within 5 s) and
  live sandbox fill are D-era / market-session evidence, explicitly NOT claimed here.
