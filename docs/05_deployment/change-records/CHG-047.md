## Summary

This change delivers the offline-provable slice of plan Task 8 (full local system): the private
execution / arrow-egress network contract, the no-production-credential / no-live-route proof, and
the checkpoint-completion job gate. The genuinely live legs of T8 (building the Rust/Go/Flink
images and running `docker compose up` against a real cluster) remain the env-gated final step,
mirroring the T5/T6/T7 records - there is no Docker daemon or live Fluss cluster in the offline
test environment.

### 1. Compose execution contract (offline, credential-free)
`t8_sandbox_contract_check.py` parses `docker-compose.yml` and `.env.example` and asserts every
execution-sandbox invariant that is provable without a daemon:
- `execution-net` is `internal: true` (private execution traffic) and `arrow-egress` exists.
- Only `execution-bridge` attaches to `arrow-egress`; gateway/Fluss/Flink/compute cannot route to
  Arrow (direct Arrow-isolation proof).
- `execution-bridge` and any gateway expose zero host `ports:` (no public execution route).
- `EXECUTION_BRIDGE_MODE` defaults to `disabled` (resolved from `${...:-disabled}`), never `live`;
  `EXECUTION_ENABLED` never defaults true; executor/action-capture remain commented/disabled.
- The compute service passes no `ARROW_*` environment variable (Arrow isolation from the jobs).
- `.env.example` secret placeholders are blank (no embedded production credentials).
- `submit-jobs.sh` wires a checkpoint poll and never passes Arrow env.

### 2. Checkpoint-completion job gate
`submit-jobs.sh` now waits, after each job reaches `RUNNING`, for the Flink REST
`/jobs/<id>/checkpoints` response to show `counts.completed > 0`, and fails closed if either
Signal or Babysitter runs but never completes a checkpoint. Bash syntax (`bash -n`) verified.

### 3. Fake-lifecycle and restart coverage
The gateway offline suite re-run green for this record proves the intent-handling boundary that
turns a halted intent into zero broker calls and recovers after restart: durable duplicate on
first handoff, restart-with-warm-durable-set skips duplicate, changed-hash-after-restart is a hash
violation, only-forward projection-ledger transitions, resumable failed position step, and the
readiness rule that health never implies execution readiness.
