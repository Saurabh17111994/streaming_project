## What happened

ING-UNIT-023 (CHG-032) revived the CHG-015 drain regression as an in-process test — but the
in-process shape deliberately skips the *hook layer*: `mainThread` capture, hook
registration, and the bounded main-thread join that lets the loop flush its final
`bridge loop ended` report before the JVM halts. This record closes that gap with a
companion test that drives the real path end-to-end.

## What the test proves

A spawned driver JVM (`BridgeShutdownDriver`, mirroring `IngestionService.main()`'s
shutdown wiring with the ING-DQ-010 seam + the CHG-032 scripted fake bridge) runs the real
`runWithBridge` loop. The test sends a **real SIGTERM**; the JVM's actual shutdown hook runs
`shutdown()` on the hook thread:

1. `signalBridge` → `kill -TERM` the fake bridge (pipes preserved) → the bridge's TERM trap
   writes the FINAL `arrow-tick-counts` report to stderr and exits 0.
2. `waitFor(10 s)` → join the stderr drain thread (5 s) → the final report is re-logged.
3. Uncertainty journal written (exactly one entry).
4. `running = false` → the main loop unwinds → `bridge loop ended` → the hook's bounded
   `mainThread.join(10 s)` lets main finish before the JVM halts.

Assertions: exit **143** (128 + SIGTERM — a hung hook or join stalls the 30 s `waitFor` and
fails), final report drained **after** the signal line, no `stderr drain error`,
`bridge loop ended` present (the join-path observable — without the join the halt races the
main thread's final flush), exactly one journal entry.

**Reflection note:** the superseded `a980a33` draft accessed `service.mainThread` and
`service::shutdown` directly; both are private in the current `IngestionService`, so the
driver wires them through `setAccessible` reflection (the draft never compiled against this
revision).
