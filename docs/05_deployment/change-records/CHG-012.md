## What landed

**ING-TCP-002 (G3 — comparator untested):** new `tests/test_reconcile_compare.py` (20 unittest cases) covering parse functions and the CLI: exact-equality pass, lost/extra ticks fail in both `--exact` and default `>=` modes, vanished tokens fail, unexpected sink tokens fail, the Fluss `-1` sentinel is tolerated, `quar` mode rejects RAW>0 while `raw`/`total` modes tolerate quarantine rows, chunked 20-token bridge reports parse, and **missing/empty/truncated evidence files fail closed**. The test drove out a real fail-open bug: an empty (truncated) bridge file reconciled as a vacuous PASS — `reconcile-compare.py` now exits 1 with `MISMATCH ... empty or truncated` when the bridge or post-probe file parses to zero tokens.

**ING-UNIT-018 (G7 — parity by convention only):** a single 11-key `ARROW_HFT_*` policy table mirrored in `ConfigParityTest.java` (4 test methods: defaults / accepted / rejected / non-integer, via `exactInt`/`intRange`) and `hft_policy_test.go` (table-driven defaults + accepts, 13 exec-self subprocess cases proving FATAL exit 2 on non-pin / out-of-range / non-integer values). The table drove out a real divergence: the Go bridge read `ARROW_HFT_LATENCY_MS` and `ARROW_HFT_CONNECTIONS` inline with **fail-open** semantics (a non-integer was silently ignored; LATENCY had no upper bound) while Java's `intRange`/`exactInt` reject them — both now flow through `hftRange`/`hftPin`, making the parity uniform and fail-closed.

**ING-UNIT-019 (env-key doc drift):** `docs_audit.py` gains **C16** (`c16_env_key_drift`): parses the 03-ingestion.md "Configuration contract" table and asserts every documented env key is referenced by `IngestionConfig`, the Go bridge, or another ingestion source. PASS on the current table (43 documented keys, all read).

**CI wiring (M2 done-right):** the checks now fail CI, not just local runs — `run-monday-gates.sh` gains a Python-unit-suite step (`tests/`, incl. the ING-TCP-002 comparator suite, no cluster needed) and a docs-audit step placed AFTER the Java gate (so C6 test-count vs surefire reports is fresh; covers C16 + C14). `run-full-suite.sh` gains a fast-fail Stage 0a running the Python suites before any build.
