## Summary

Delivers the **step-1 live proof** of WP-4 (T6): the real `FlussProjectionWriter` in the execution
gateway is now exercised end-to-end against a live Fluss cluster, writing a normalized execution
event (audit/fill/lifecycle/position/correlation) into projection tables and reading the KV
projections back via `Lookuper`. This closes the concrete step-1 gap: the existing
`GatewayFlussDurableReplayIntegrationTest` drives a **fake** `RecordingSink` writer, so no test
previously proved the *actual* `FlussProjectionWriter` lands rows in Fluss.

**WP-4 is complete.** This record covers all four plan steps, now live/cross-language verified:
1. Step 1 — the real `FlussProjectionWriter` writes projections to Fluss (live-verified).
2. Step 2 — Rust normalized Nautilus-envelope emitter (`src/projection/mod.rs`), a faithful port of
   the JVM `PositionProjector`/`PositionProjectorDriver` arithmetic (the seam WP-2 will reuse).
3. Step 3 — T1 durable quarantine/audit writer (`FlussPostbackQuarantineStore`, live-verified appending
   to the `Postback_Quarantine` LOG and reading it back via log scan).
4. Differential parity — Rust emitter reproduces the JVM `PositionProjectorDriver` oracle
   field-for-field for the same fill sequence + the oversell -> VIOLATION negative (cross-language).

## What changed

- **Added** `FlussProjectionWriterIntegrationTest` (env-gated on `FLUSS_BOOTSTRAP`, `@Tag("fluss")`):
  - creates a scratch database + the five projection tables (mirroring
    `08_fills.sql` / `09_order_lifecycle.sql` / `10_positions.sql` / `13_order_correlation.sql` /
    `14_execution_audit.sql` column order),
  - opens the **real** `FlussProjectionWriter` (no fake), drives `writeAudit` / `writeLifecycle` /
    `writePosition` with a full `NormalizedExecutionEvent`,
  - reads back the KV tables (`Positions`, `Order_Lifecycle`, `Order_Correlation`) via `Lookuper`
    and asserts the rows,
  - re-drives the same event and asserts upsert-by-key idempotency (`Positions.source_event_id`
    stays the single `postback_event_id`).
- No production code / DDL changed.

## What changed (steps 2-3 + parity, this extension of CHG-052)

- **Rust emitter** (`code/02_services/04_executor/src/projection/mod.rs`, new, registered as
  `pub mod projection;`): faithful Rust port of the JVM projection core — `PositionProjector` /
  `PositionProjectorDriver` / `KvStateUpdateProtocol` / `PositionLifecycle` / `PositionSnapshot` /
  `FillEvent`, deterministic `position_id` minting, and `ProjectionEmitter::emit_fill` lifting a
  `ReportEnvelope` into the projected Positions row. i64 arithmetic mirrors Java `long` (truncating
  division, wrapping ops) so parity is bit-identical.
- **T1 durable quarantine/audit writer** (`code/common/.../projection/FlussPostbackQuarantineStore.java`):
  Fluss-backed `PostbackQuarantineStore` appending to the `Postback_Quarantine` LOG table; env-gated
  live test reads the appended row back via `LogScanner`.
- **Differential parity**: `DifferentialParityFixtureTest` (Java) drives the real
  `PositionProjectorDriver` and prints its output, pinned as `tests/fixtures/positions_oracle.json`;
  `tests/differential_parity.rs` (Rust) reproduces the same scenario and asserts every projected
  snapshot equals the oracle field-for-field + the oversell VIOLATION negative.
- No production code path / DDL changed (Rust additions are a new library module, unreferenced by the
  live binary).
