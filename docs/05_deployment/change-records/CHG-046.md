## Summary

This change completes the Babysitter position-observation boundary (plan Task 7): the
`fromElements(0L)` MVP marker source is replaced with a real `Positions` KV changelog observer
that checkpoints observation state and emits zero `Position_Actions` under every input.

### 1. Positions changelog source replaces the marker
`BabysitterJob.buildTopology` now wires a `FlussSource<RowData>` over the versioned `Positions`
KV table with full snapshot+changelog offsets (`OffsetsInitializer.full()`), a current-value
`RowKind` filter (INSERT/UPDATE_AFTER only - BEFORE/DELETE carry no full image), a validated
snapshot deserializer, a keyed observation operator, and a deliberate no-op terminal sink. The
pinned operator UIDs (`positions-changelog`, `babysitter-rowkind-filter`,
`babysitter-position-deserialize`, `babysitter-position-observation`, `babysitter-discard`)
anchor checkpoint/restore. The generating pipeline is split out as
`attachObservationPipeline(DataStream<RowData>, config)` so the exact production operators are
cluster-free inspectable (the `FlussSource.build()` performs a live `Admin.getTableInfo`, so it is
isolated to `buildTopology`).

### 2. Checkpoint and restore behavior
`buildTopology` enables checkpointing and points a durable `CHECKPOINTS_DIRECTORY` (from
`BABYSITTER_CHECKPOINT_DIR`, mirroring the proven SignalJob pattern). The operator retains the
latest accepted source version, source event id, last-update timestamp, and schema version per
`position_id` in checkpointed `ValueState`. `PositionsObservationOperatorTest` proves the state is
snapshot/restored across a fresh harness instance: after restore a replayed v1 is a DUPLICATE
no-op (not a re-apply) and a clean v3 applies on the restored base.

### 3. Version-gate disposition (KvStateUpdateProtocol)
The operator applies `KvStateUpdateProtocol`: a clean newer version is APPLIED; same
version/same event is DUPLICATE (no-op); an older version is STALE/REGRESSION; an equal-version
different-content is CONFLICT. Ambiguous dispositions are never applied. Each row's disposition is
emitted on an observability side output (routed to no sink; readable by tests/health), while the
MAIN output stays empty - zero `Position_Actions`, zero persistence, zero broker calls by
construction.

### 4. Zero-action and no-broker proof
`BabysitterJobTest` (BAB-UNIT-001/003) inspects the generated `StreamGraph` cluster-free: no node
emits/sinks `Position_Actions`; the sole sink is the `babysitter-discard` no-op; no Arrow,
lifecycle, position, or execution output exists in the write path. `POSITION_ACTIONS_ENABLED` must
be unset or `false` and required config fails closed (`BabysitterConfigTest`,
`BabysitterConfig.fromEnv`). The env-gated live MiniCluster test
`BabysitterPositionsRestoreIntegrationTest` (COMPUTE_INT_TEST_T7) runs the real graph against a
real Fluss `Positions` table, checkpoints, restores on a fresh worker, and asserts no
`Position_Actions`/execution table is ever created and `Positions` is never mutated beyond the
test's own writes.

## Remaining T7 wiring (not closed by this change)
The offline engine, version gate, checkpoint/restore, and zero-action/no-broker proofs are
implemented and green (full compute Maven suite: 336 tests). The env-gated MiniCluster + live
Fluss restore run (COMPUTE_INT_TEST_T7) is written and compiles but requires a dev Fluss cluster
to execute; the production `submit-jobs.sh` launcher wiring awaits the Task 8 runtime step.
