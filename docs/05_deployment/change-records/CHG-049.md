## Summary

Implements the production `BridgeClient` transport against the real Go execution bridge and
fixes a latent wire-contract bug that prevented Rust-to-Go interop. This is the first concrete
RP − "reuse the existing Go execution bridge (fake profile)" — and closes part of the T3/T4
"no production BridgeClient" live boundary.

## What changed

- **New `src/bridge/transport.rs`** — `HttpBridgeClient` implementing the existing
  [`BridgeClient`](code/02_services/04_executor/src/bridge/client.rs) seam: `POST /v1/commands`
  (returns `ReportEnvelope`), `GET /healthz` (reachability probe, no broker credentials), Bearer
  auth, loopback-only. Minimal HTTP/1.1 client over `tokio` TcpStream (content-length / chunked /
  read-to-close framing) — **no new dependencies**; reuses pinned `tokio`/`serde_json`/`async-trait`.
- **Wire-contract fix in `src/bridge/protocol.rs`** — the three wire types
  (`CommandEnvelope`, `OrderCommand`, `ReportEnvelope`) were serialized **camelCase**
  (`recordType`, `transactionType`…) but the real Go bridge is **snake_case**
  (`record_type`, `transaction_type`…). Changed `rename_all = "camelCase"` → `rename_all =
  "snake_case"` and updated the protocol JSON test. The in-process `FakeBridge` path (typed
  structs) is unaffected.
- **`src/bridge/mod.rs`** — registered `pub mod transport;` and re-exported `HttpBridgeClient`.

## What did NOT change

- `take_reports()` still returns `None` (WebSocket `/v1/events` report intake via the already
  pinned `tokio-tungstenite` is a later step).
- No running `LiveNode` / OMS / risk / portfolio wiring — deferred per user scope (WP-2).
- No live-Arrow credentials are read, and the Go bridge remains `fake`-profile only.
