## Summary

Task B2 of the live-readiness master plan: composite crash-window proof that
the durable command gate satisfies the money-safety invariant end-to-end —
the bridge sees each order EXACTLY ONCE across a `kill -9` injected between
"durable intent" (`SUBMITTING`) and "bridge ack recorded".

## What the proof pins down

1. Restart on an ambiguous attempt always yields `UnknownHalted` + partition
   halt; bridge call count never increments on any replay.
2. Exactly one durable attempt record per instruction; broker id is recorded
   only from a terminal bridge/reconciliation outcome, never guessed.
3. An epoch bump does NOT fence away an unresolved attempt — it stays
   quarantined (`UnknownHalted`, re-halt on replay) until human
   reconciliation corrects the durable record by broker evidence. This is a
   stricter guarantee than the plan's original "second run rejected"
   wording and is now the documented contract.
4. After reconciliation + re-enable (epoch 6→7, fence 8→9) fresh orders flow
   again, one bridge call each; the store converges to one record per
   attempt.
