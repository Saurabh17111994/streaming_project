## What landed

**M3 — Failure-path E2E (plan §3, §2.4, §2.9):** four new tests close the
plan's remaining failure-path gaps, all default-run via the ING-DQ-010 no-op
sink seam (no live Fluss, no broker):

| Test | Proves |
| --- | --- |
| `BridgeCrashLoopE2ETest` (ING-FAIL-008) | A scripted fake bridge binary that exits non-zero is driven through the REAL `runWithBridge` subprocess loop: each unexpected exit logs `BRIDGE_CRASH` and writes a DROP discontinuity, the bridge restarts exactly once (attempt 1 of 2), the second crash is TERMINAL, the service unwinds to a clean single shutdown, and the readiness marker is cleared |
| `BridgeAuthFailureE2ETest` (ING-FAIL-009) | Revoked creds: the scripted bridge mirrors the real drain sequence (`auth_failure` → `bridge_shutdown` → exit 2); Java logs the authentication failure, writes `auth_failure` DROP evidence (reason preserved), appends ZERO ticks, and does NOT restart the bridge (terminal, not retryable) |
| `ShutdownDeadlockTest` (ING-FAIL-010) | A Fluss ack that never completes (un-cancelable future): `shutdown()` returns within the drain deadline (no hang), the uncertainty journal pins the exact remaining pending bytes (R-260), and a second `shutdown()` is a no-op (single journal entry, single drain) |
| `ReadinessGatingMatrixTest` (ING-INT-005, closes G8) | Exhaustive walk of every `HealthProbe.isReady()` dimension (liveness, Fluss, tracker, broker, subscription, data, frame recency, clock): ready only when all eight are true; false when ANY single one is false (incl. partial ack, no tracked slot, stale frame, fail-closed unverified clock) |

**Two small production changes shipped with the tests:**

1. **`DRAIN_DEADLINE_SECONDS`** (IngestionConfig, default 30, range 1-300) —
   the drain deadline was hardcoded 30 s in `RawTickWriter` construction. The
   deadlock test needs a provable deadline (2 s) so "exits within the drain
   deadline" is asserted in-test instead of waiting out 30 s. Default is
   byte-identical to the old behavior; the key is documented in the
   `03-ingestion.md` Configuration contract table (C16 re-PASSed).

2. **`pending_records` / `pending_bytes` on the uncertainty journal entry**
   (UncertaintyJournal.Entry + the `shutdown()` call) — the entry previously
   recorded only cumulative totals; R-260 demands the EXACT bytes still
   pending at shutdown (what the drain was unable to flush). Additive fields;
   `UncertaintyJournalTest` updated to construct and assert them.

**Log capture note:** the repo ships a slimmed log4j-core (no `ListAppender`),
so the bridge tests capture logs with a minimal `AbstractAppender` subclass on
the root logger (attached/detached per test, no config mutation).
