## What landed

1. **Uncommented the `compute:` compose service** (was commented since the
   execution-core re-architecture, CHG-053 era). On `docker compose up`, the
   compute container now runs `submit-jobs.sh`, which submits the Flink jobs
   and waits for each to reach RUNNING + one completed checkpoint (T8 local
   readiness gate).

2. **submit-jobs.sh now submits three jobs** (was two):
   - `signal-job-compute` (unchanged entry class)
   - `Babysitter MVP no-op job` (unchanged)
   - `SafetyHaltJob` (slot-scoped `Safety_Halt_Requests` consumer,
     SAFETY-INT-001) — **gated on `SAFETY_MANIFEST_TOKENS`**: the job fails at
     startup without it (comma-separated instrument tokens). Dev default:
     unset → skip with a warning (safety consumer not deployed). Production
     MUST set it (fail-closed).

3. **F005 fail-closed replay guard in submit_job()**: the compose
   `flink-common` anchor sets `ALLOW_FULL_REPLAY=true` by default — without a
   guard, a stack restart would silently submit signal-job as an offset-0 full
   replay (re-emits the whole backlog, balloons dedup MapState past the pinned
   checkpoint contract, appends duplicate rows to the immutable
   `Signal_Candidates` LOG; observed 2026-08-10). The guard refuses signal-job
   submission when ALL of:
   - entry class is `com.trading.compute.signaljob.SignalJob`
   - `STATE_RECOVERY_PATH` unset
   - `ALLOW_FULL_REPLAY=true` (from env/compose)
   - `COMPUTE_ALLOW_REPLAY != 1` (operator override unset)
   
   Resolution: set `STATE_RECOVERY_PATH=<savepoint|checkpoint>` to resume, or
   `COMPUTE_ALLOW_REPLAY=1` to explicitly approve a full-replay bootstrap
   (first-ever deploy). Babysitter/SafetyHalt are unaffected (guard is
   signal-job-scoped).

## Why

The stale-code audit (2026-08-26) found SUSP-1/SUSP-2: BabysitterJob and
SafetyHaltJob existed but were never deployed — the compute service that runs
their launcher was commented out. Enabling it without the F005 guard would
have introduced the silent-replay hazard on the next stack restart. Both are
addressed in one change so the compute service is safe to enable.

## Compatibility

COMPATIBLE — no DDL, schema, wire format, or Flink state layout change. The
running signal-job is unaffected (already rolled out from savepoint via
`make rollout-savepoint` on 2026-08-26, job `df0ef888...`). The guard only
affects future launches.
