## What landed

**Phase A item 3 — the externalization benchmark** (DEC-038 §9 measurement
requirement) plus **two evidence-gated cleanup bugs the run surfaced and
fixed** (SIG-STATE-001).

| Piece | Detail |
| --- | --- |
| `FingerprintDedupExternalizationBenchmarkIT` (new, env-gated) | Live-cluster harness against a scratch `fingerprint_dedup`-shaped table through the PRODUCTION `FlussFingerprintDedupStateStore`: write phase (shared-writer bulk + `putFirstSeen` store path), sizing, cold-restart hydration, bounded re-entrant cleanup, post-delete read-path verification, final plateau. Evidence file: `logs/tracker-14/p11-dedup-externalization-benchmark-20260815.md`. |
| **Fix 1 — bucket scoping** | `bucketOf` was `token % numBuckets`; Fluss assigns via `KeyEncoder.ofBucketKeyEncoder(rowType, bucketKeys, lake)` + `BucketingFunction.of(lake)` (dev default `lake=iceberg`). Verified predicted==actual on the live cluster. Fix = `DedupBucketAssigner` (Fluss's own public API, pure + unit-testable). Without it `scanExpired` read the wrong bucket and cleanup silently missed expired rows. |
| **Fix 2 — delete row shape** | `UpsertWriter.delete` runs `checkFieldCount` and requires the full 6-column row, not the 3-field PK row (latent — never reached while Fix 1 was broken). The store rebuilds the full row from the candidate's `firstSeenMs`/`expiryMs`. |
| Benchmark results (PASS) | 73 == 58+15 sizing; 15/15 cold-restart hydration SEEN_LIVE (~102 ms/lookup); **15/15 stale rows deleted** across 3 bounded passes; post-delete NOT_SEEN; final plateau **58 == live 58**. Measured dev-cluster costs: ~105 ms/durable-ack write, ~325 ms/`putFirstSeen` (per-call writer), 5 s leader-election settle after CREATE. |
