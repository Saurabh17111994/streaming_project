## Summary

Non-market (HALTED-path) half of B4.2 proven live end-to-end through the real
modules against the local Fluss cluster (`FLUSS_BOOTSTRAP=localhost:9123` —
docker-compose zookeeper/coordinator/tablet + the platform catalog already
carrying all 26 tables; the sanctioned DDL-apply container correctly REFUSED
on its empty-catalog precondition, itself proof the catalog is populated):

* **Compute**: `B4SignalIntentE2ETest` drives the real `SignalJob` topology from
  hand-written raw ticks (7 rising 15 s event-time windows + flush tick, pinned
  `CANDLE_WINDOW_MS=15000`, rule-v1 breakout, lookback=2) → `Signal_Candidates`
  LOG rows → — only with `EXECUTION_INTENT_ENABLED=true` — immutable
  `Execution_Intent` rows (unique `instruction_id`, non-blank `request_hash`,
  `schema_version=1`, `side=BUY`, `quantity=1`, config-derived
  account/partition; LOG never shrinks). Disabled-by-default twin: signals
  flow, **zero** intents — the fail-closed guarantee proven live, not just in
  B4.1 unit tests.
* **Gateway**: `B4HaltedIntentConsumeDeferE2ETest` writes a canonical intent
  into a scratch catalog; real `IntentReader` + `DurableIntentDispatcher` +
  `NautilusIntentClient` consume it; with no ENABLED `Execution_Gate` row and
  no durable fence token the handoff is **DEFERRED**: readiness
  protocol/fluss NOT_READY, zero `Execution_Attempts`/`Order_Lifecycle`,
  intent NOT committed as processed (replayable) — the wall before any order.
* Reproducible runner: `code/01_platform/04_scripts/run-b4-halted-e2e.sh`.

Honest: the FULL fill leg (attempts → `Order_Lifecycle` → `Fills`) remains
gated on A2.3/A2.4 sandbox config (`BI-EQ ×1`) + T4 bridge wiring — D-era
market-session batch, unchanged. No broker touched this turn.

## Decisions

- **Blame-free debug kept as evidence**: two pinned-config guards (CANDLE
  window, canonical configuration version) fired during bring-up — fixed by
  setting the pinned values; then a false "intents in the disabled run" was
  traced to stale same-token rows in the immutable LOG (LogScanner replays
  from offset 0) — fixed by clock-derived per-run tokens + `created_ts` window,
  which is the same hygiene production consumers need when replaying an
  immutable intent log.
- **Why test now**: proves both directional halves of B4.2 safely (fail-closed
  path) before authorization scope grows, satisfies "evidence before scope"
  for the laptop session, and de-risks the A-era bridge work.
