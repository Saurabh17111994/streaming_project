# CHG-105 — rollout-savepoint job auto-resolve fix + live re-verification

`rollout-savepoint.sh` could not auto-resolve the running job by name: the
fixed-order sed regex expected `"jid","name","isStoppable","state"` in that
exact sequence, but this Flink version's `/jobs/overview` omits `isStoppable`
entirely and uses `jid,name,start-time,end-time,duration,state`. The regex
never matched, so the script always failed with "no RUNNING job named ..."
unless the operator passed `JOB_ID=` explicitly (as the 2026-08-24 live run
did). No product code, no runtime/DDL/state change.

## Change

The preflight job-name resolution in `rollout-savepoint.sh` used:

```bash
sed -n "s/.*\"jid\":\"\([0-9a-f]\{32\}\)\",\"name\":\"$JOB_NAME\",\"isStoppable\":\(true\|false\),\"state\":\"RUNNING\".*/\1/p"
```

Flink 2.2.1's `GET /jobs/overview` returns objects shaped
`{"jid":..., "name":..., "start-time":..., "end-time":..., "duration":..., "state":...}`
— no `isStoppable` field, and `start-time` between `name` and `state`. The
regex therefore never matched and auto-resolve was dead code (worked around
with `JOB_ID=` on 2026-08-24). Replaced with a field-order/omission-tolerant
extraction: isolate each job object (`{"jid":"<32 hex>", ... "state":"..."}`),
then require `name` + `state=RUNNING` and pull the jid.
