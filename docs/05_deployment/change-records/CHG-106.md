# CHG-106 — /v1/intents `action: "amend"` (modify order) implemented

The gateway → nautilus intent path supported `place` and `cancel` but rejected
`amend` with 422 `unsupported action` — the modify-order half of the
place/modify/cancel lifecycle was missing at the intent-mapping layer (the
Go bridge already had a full `Modify`/`Cancel` implementation). This change
implements the amend mapping, wires it into the router, and closes the
lifecycle. No runtime/topology/DDL/state change.

## Change

1. **`intent::amend_envelope_from_payload`** — mirrors `cancel_envelope_from_payload`
   (fresh `execution_attempt_id`, deterministic 14-hex `client_order_ref` over
   `v1|instruction_id|execution_attempt_id`) but for `Command::Modify` with a
   required `broker_order_id` (the bridge's modify keys on the broker id —
   `validateCommand` rejects a modify without one) and the amended `order`
   block (same schema as place: symbol/exchange/side/order_type/quantity/
   limit_price_paise/product_type/time_in_force). Fails closed on any
   unsupported value (422, never forwards a half-mapped order).
2. **Shared `order_command_from_payload`** — the order-block mapping is now one
   helper used by both place and amend (no duplicated logic).
3. **http.rs action discriminator** — `"amend"` now maps to the new function;
   anything else still fails closed 422 (`unsupported action`).
