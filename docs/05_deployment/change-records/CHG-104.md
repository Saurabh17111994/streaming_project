# CHG-104 — chaos-03 tablet-kill test-harness fix: probe-based recovery detection

The chaos-03 tablet-kill drill failed reproducibly (3/3) with `raw_table_1 not
readable within 180s of tablet restart` even though the data plane recovered
cleanly (post-recovery scans returned the exact pre-kill row count). Root cause
was a test-harness bug — the recovery loop conflated "is the table serving
reads" (a small probe) with "full-log rescan of 11.5M rows" (minutes on this
dev box), and the 60s per-attempt bound aborted scans that were making
progress. No product code, no data loss, no DDL change.

## Change

`TabletKillChaosIntegrationTest` previously detected recovery by running the
FULL invariant scan (whole-log rescan from offset 0) inside the 180s recovery
window, with a 60s per-attempt bound. On this dev box the full scan of 11.5M
rows takes ~3m49s (measured 2026-08-25), so every post-kill attempt was
aborted at 60s and the 180s window expired while the tablet was actually
recovering fine.

Fix splits recovery detection from invariant verification:

1. **`probeReadable()`** — subscribes to bucket 0 only, polls with 500ms
   timeouts for up to 30s; returns true as soon as records flow OR 4 clean
   empty polls prove the leader is serving. Detected recovery in **5s** on the
   re-run (vs. the old loop burning the whole 180s window).
2. **Post-recovery invariant scan** — runs once the probe passes, bounded by
   `CHAOS_POST_KILL_SCAN_BOUND_SEC` (default 600s, enough for the ~4 min
   full-log rescan), retrying on the documented loading/metadata races.
