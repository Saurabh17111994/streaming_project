## Summary

After setting `T9_APPROVED_BY=saurabh` and running the A2 live harness, three real
defects surfaced and were fixed:

1. **Harness live transport was a stub** — `DockerExecTransport.http_json` inherited
   a `NotImplementedError`; `--live` crashed instead of classifying. Implemented as an
   in-network HTTP call via `docker run --rm --network 01_docker_execution-net curlimages/curl:latest`
   (no host ports — T8 gate 3); probe/tool failures return status 0 and are classified
   BLOCKED (probe-unavailable), never pass/fail.
2. **Cross-language gateway protocol parity** — `serde_json`'s default `Map` is a
   BTreeMap: the Rust `gateway_protocol.rs` re-serialized the payload with SORTED keys,
   while Java (`GatewayProtocol.java` — Jackson `ObjectNode`, insertion order) and Python
   (harness `encode_envelope`) canonicalize in insertion order. Any real envelope failed
   `authentication failed` (HMAC over differing payload_json). Fixed by enabling
   `preserve_order` so serde_json matches Jackson. Existing Rust↔Rust tests could not
   catch this — the first cross-language envelope (today's live run) did.
3. **Nautilus production boot abort (latent)** — `main.rs` initialized our tracing
   telemetry (whose `tracing-log` bridge registers the process-wide `log` logger) BEFORE
   `LiveNodeRuntime::build_with_bridge`; Nautilus's kernel then failed its own
   `set_boxed_logger` ("A non-Nautilus logger is already registered") and the service
   aborted at boot. The previously-running container had a stale image (built before
   `build_with_bridge`), hiding the defect until the first real image rebuild. Fixed by
   boot ordering: Nautilus kernel owns the `log` logger; our tracing subscriber is
   installed after (independent system — tracing events still work).

Also: `.env` gained `T9_APPROVED_BY=saurabh` (execution-safety section) — the harness
reads that variable from its own process env (`approval_gate()` fails closed).

## Decisions

- **preserve_order not sorted-in-Python**: the reference is the Java signer (insertion
  order); making Python sort would fix Python↔Rust but break Java↔Rust (the production
  signer is `06_execution_gateway`).
- **Boot order (kernel first) over swallowing the kernel error**: the kernel's own
  recovery (`LogGuard::new`) can't succeed when a foreign logger owns `log`; ordering
  matches upstream ownership (Nautilus owns `log` in a hosted node).
- **T9_APPROVED_BY stays process-env**: no compose/container wiring exists or is needed —
  the harness reads `os.environ` only; containers never see this variable.
