## What happened

Three turns of gate work consolidated into one record — all aimed at the same class of
failure: **machine-validated truths that only fail when someone thinks to run the gate**.

### 1. Scanner LIVE-STALE tier — the now/current masking class

The stale-claim scanner's `classify_numeric` marked a count claim LINE-ANNOTATED when a date
marker sat within its annotation window of the count — regardless of whether the claim was
*historical* ("as of …") or a *live* "now N" statement. That let "now 234/0/8-skips, common
340/0/1-skip" ride on an adjacent `2026-08-15` marker while the suite had long since moved to
236/341. The fix:

- **New `LIVE-STALE` failing tier** (rank 0, above UNANNOTATED): a `now/currently/current N`
  claim within 60 chars before a count forces this tier no matter what date sits nearby.
- **New `live-count-stale` claim type** for *bare* suite triples ("now 234/0/8-skips" with no
  module word) — the exact form the old module-word-anchored regex structurally could not see.
- **Status-word exclusion** (`LIVE_MARKER_BAD`): "the manifest is current"/"remains current"
  is a predicate, not a live count — those claims keep their date annotation.
- **Live-marker gap 50 → 25** so "now has an implementing test (suite 330/0/17" (a *now-that*
  clause) stops matching.
- **Tier in the dedup key**: a dated claim on the same line can no longer hide a live one.
- **10 unit tests** in `test_stale_table_kind_scan.py` pinning the masking class (the old
  234/340 case now asserts LIVE-STALE), truth filtering, the C6 carve-out, now-that
  exclusion, status-word exclusion, and the gap shrink.

The hardened scanner then surfaced the fixes it was designed to catch: `02-schema-storage.md`
and `11-testing-and-release.md` current-totals `340 → 341` common, and `04-signal-job.md`
line 992 (exposed by the tier-in-key change) gained an adjacent `2026-08-13 measurement`
marker. The `11-testing-and-release.md` "current suite 292/0/17" was reworded to the dated
"the suite **stood at**" so a historical claim cannot masquerade as live.

### 2. Monday-gate SIGTERM-drain pin (step 12/12)

ING-UNIT-023/024 (CHG-032/033) are default-run, so they already executed inside the Monday
gate's full-module Java step — but only as part of a 236-test run, where a silent surefire
exclusion or test rename could drop them unnoticed. Step 12/12 pins them **by name** with the
same `-Dtest` + `failIfNoSpecifiedTests=false` idiom as the Schema/Perf certification step,
giving the CHG-015 drain regression its own SUMMARY line and evidence log. Placed after the
docs-audit step so C6 keeps reading the full-suite surefire reports.

### 3. full_audit.sh boundary + a pre-existing Layer 2a fix

`full_audit.sh` never executes tests — it is the doc-truth command (three machine gates +
beyond-scanner sweeps + dossier-trio coherence). Its header now states the boundary
explicitly: executable test pins live in `run-monday-gates.sh`; a mvn step here would clobber
the surefire reports Layer 1b's docs-audit C6 reads.

Running `make full-audit` end-to-end exposed a **pre-existing failure at HEAD**: Layer 2a's
ranking/reservation sweep flagged `07-executor.md` because the annotation "**(Ranking/
instruction feed REMOVED 2026-08-15, CHG-005.)**" was wrapped across two lines — the line
containing "Ranking" lacked the whitelist keyword "REMOVED" that sat on the next line. It had
been failing silently since the CHG-026/027 consolidation. Fixed by joining the annotation
onto one line (annotate-don't-rewrite style).

### 4. Full doc audit wired into the Monday gate (step 9/12)

The rot happened because only the machine gates (docs-audit) were ever run in CI; the
beyond-scanner sweeps and trio coherence lived only in `make full-audit`, which nothing
invoked. Step 9/12 now runs `full_audit.sh` instead of `docs_audit.py` — full_audit ⊇
docs-audit (its Layer 1b), so the sweeps + trio are added with no redundancy and the C6
ordering invariant is preserved (after the Java gate, before the narrow `-Dtest` steps).
`run-full-suite.sh`'s Stage 1 description updated to match; its Stage 1 delegates to
run-monday-gates.sh, so the soak suite inherits the audit too.
