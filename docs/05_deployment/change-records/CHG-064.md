## Summary

Closes the B8 gap: `CLOCK_OFFSET_LIMIT_MS` was declared in compose for the
ingestion service only; nothing on the execution side read or enforced any
drift limit. The execution service now owns the same key
(`ServiceConfig.clock_offset_limit_ms`, default 200 ms) and enforces it
fail-closed through a new `DriftMonitor`:

- `|offset| > limit` → `Gate::safety_halt()` + error alert; approvals cleared;
  recovery ONLY via the sanctioned reconcile → approval → enable path.
- Unmeasurable offset (probe failure) fails closed identically.
- Within-limit samples never touch the gate and never auto-recover a halt.

The production NTP `OffsetSource` is wired at Workstream D (VM era) behind the
same trait — identical swap pattern to the durable stores.
