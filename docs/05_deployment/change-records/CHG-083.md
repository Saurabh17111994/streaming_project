## Summary

Stages the E5b.2 verifier so the moment the E5b.1 token lands it can run as-is:

* `code/01_platform/04_scripts/r2_legal_hold_check.py` — three checks (plan E5b.2):
  1. **bucket_lock** — enabled indefinite (or >=1-year dated) Cloudflare bucket-lock
     rule covering every audit prefix, via the CF API (`cf_get_bucket_lock` reuse).
  2. **retrieval** — ListObjectsV2 + sampled manifest GETs, each object's SHA-256
     folded into the evidence.
  3. **hash_chain** — spot-check against `AuditHashChain` (Java): a **byte-exact
     Python port** of `Manifest.canonical()`/`hash()`/`linkedHashes()`/`rootHash()`/
     `verifyChain()`, cross-verified against the real JVM output (constants baked
     into the tests). A published `_root.txt` object binds the sample root (else the
     chain is honestly reported `UNVERIFIED-ROOT`, never faked VALID).
* Modes: `--chain-dir` (offline, runs today), `--validate` (full R2 run — exit 2
  until the E5b.1 token), `--self-check` (offline fake-cloud demo).
* Documented the **object contract** the future EOD/offload writer must match:
  canonical-text manifests at `<audit_prefix><table>/<YYYY-MM-DD>.manifest`, optional
  `<audit_prefix>_root.txt`.

## 3. Limitation recorded honestly (E5b.3)

**R2 bucket locks != S3 Object Lock** (the S3 Object Lock API returns
`ObjectLockConfigurationNotFoundError` on R2). The WORM-equivalent is an
indefinite/dated Cloudflare bucket-lock rule on the audit prefix (NFR 3.4.1; set via
the dashboard/Wrangler/Cloudflare API, and read back programmatically here). Residual
risk: a compromised credential with lock-admin scope could still drop the lock —
mitigated by the scoped E5b.1 token, the deletion-control review, and the hash-chain
binding. This limitation is written into the evidence record automatically.
