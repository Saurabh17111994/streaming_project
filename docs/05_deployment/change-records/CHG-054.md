## Summary

Implements **DEC-044 (2026-08-21, user decision — Saurabh)**: resume from order safe-halt and
audit deletion inside retention require **a single authenticated approval by `saurabh`** for the
same gate epoch/evidence hash (or deletion scope/policy/legal-hold); a second distinct approval
is **not required and not checked**. Supersedes DEC-019 (two-person) and the two-person
audit-deletion rule. This record completes the repo-wide adoption (the decisions entry and the
Java gate/audit logic landed earlier the same day; this pass finished the executor, schema-layer
wording, the requirement/contract/operations corpus, and corrected two regressions the partial
sweep introduced).

## What changed — functional code

- **Rust executor gate (`gate.rs`):** `Gate::enable` now requires one recorded approval bound to
  the evidence hash (`EnableError::RequiresApproval`, was `RequiresTwoApprovals`); the
  `ApprovalError::SingleApprover` and `ApprovalError::EvidenceChanged` variants and the
  `approval_b` field are removed (a second approval is a no-op — not required and not checked);
  epoch declaration/match and evidence binding are unchanged; `safety_halt` still clears the
  approval + evidence (fail-closed re-approve, CONTROL-006). INVARIANT-003 reworded to "no
  ENABLED gate without an authenticated single-operator (saurabh) approval".
- **Test drivers:** `shutdown.rs` and `execution/client.rs` enable helpers migrated from
  `OPS-A`/`OPS-B` two-approval to a single `saurabh` approval. `cargo test --lib` = 125 passed /
  0 failed / 0 warnings.
- **T9 evidence:** `t9paper/mod.rs` `REVIEWERS` reduced to the single authorized reviewer
  (`["saurabh"]`; was `saurabh_reviewer_1` + `namrata_reviewer_2`).
- **Java common:** `LiveMoneyStopCondition.SAFE_HALT_RESUME_UNPROVEN` label updated; dead
  `Decision.REJECTED_REQUIRES_TWO_AUTHORIZERS` enum variant removed from
  `AuditDeletionControl`; `GateRow`/`ExecutionGateColumns`/`ExecutionGateColumnOwnership`
  javadoc reworded (approval_2 kept as an optional column, DDL unchanged).
- **DDL comment:** `11_execution_gate.sql` v3 header records DEC-044 single-operator semantics;
  no column change.
