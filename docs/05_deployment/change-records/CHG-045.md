## Summary

This change delivers the T6 state-projection/observation core as a pure-JVM, offline-test-closed
engine in `code/common` (package `com.trading.common.schema.projection`), aligned to the plan's T6
sequence and target behavior, with the Java `PositionProjector`/`PositionProjectorDriver` retained
strictly as a differential oracle.

### 1. Normalized Nautilus event envelope
`NormalizedPostback` carries `postback_event_id`, a stable `sourceSequence` (event-store/event
sequence — the authoritative monotone version), a versioned content `fingerprint`, broker/client/
platform identities, instrument/context (`side`, `instrument_token`, `exchange`, `symbol` — closing
the T6 fill-context gap), order status, cumulative/pending/fill quantities, prices, event/receive
timestamps, mapping version, and payload hash. `PostbackFingerprint` computes the versioned SHA-256
fingerprint; a mismatch is quarantined as `FINGERPRINT_MISMATCH`. The projection never infers
`side` or uses wall-clock receive time as the only version.

### 2. Correlation precedence
`PostbackCorrelator` applies `broker_order_id` → echoed `client_order_ref` → approved reconciliation
result via `CorrelationIndex`. Missing, multiple, or contradictory matches are `Postback_Quarantine`
dispositions (`MISSING_BROKER_ID`, `NO_MATCHING_INSTRUCTION`, `AMBIGUOUS_CORRELATION`), which the
driver writes to the quarantine sink, appends audit evidence, and halts the affected scope.

### 3. Lifecycle monotonicity before Order_Lifecycle
`OrderLifecycleProjector` rejects impossible quantity / fill overrun / unknown status, treats an
exact duplicate as a no-op, an older source version as stale evidence (audited, no write), an
equal-version different-content as `LIFECYCLE_CONFLICT`, and terminal regression as
`TERMINAL_REGRESSION` — each quarantine + halt via the driver.

### 4. Position serialization (no arithmetic)
`NautilusPositionEvent` is the authoritative Nautilus-computed position; `PositionProjectionWriter`
serializes it into a Positions KV row and applies the version gate without recomputing quantities —
it validates the Nautilus event's quantity/state invariants and rejects stale/conflict/inconsistent
updates. `NautilusPositionAuthority` is the boundary; in production the Rust service, offline the
parity projector.

### 5. Projection ledger + driver
`PostbackProjectionLedger` (RECEIVED → CORRELATED → AUDIT_WRITTEN → LIFECYCLE_APPLIED →
POSITION_APPLIED_OR_NOT_REQUIRED → COMPLETE, with QUARANTINED/FAILED terminal dispositions) makes
independent writes restart-safe and idempotent; the driver never marks COMPLETE before every
required write is acknowledged and carries no broker-call surface. `PostbackProjectionDriver`
orchestrates the whole flow and exposes halted scopes.

### 6. Parity and rebuild
`NautilusParityTest` proves the projection serialization reproduces the Java reference projector's
Positions rows (state, quantity pair, weighted averages, source version/event) for a valid sequence,
and that an oversell is rejected on both paths. `ProjectionRebuildDeterminismTest` proves replaying
the same captured fixture set from empty Fluss projections reproduces identical rows and ledger
completion without altering Nautilus state or issuing a broker command.

### Ownership re-scope (plan T6 TODO)
`PositionsColumnOwnership` and `OrderLifecycleColumnOwnership` now name the Nautilus projection
boundary (`nautilus-projection:position-serializer` / `...:lifecycle-serializer`) as the sole
writer instead of the retired Action Capture writer, and document that the Java projector classes
are parity-only. The foundation `OwnershipMatrix` doc mirror is intentionally left unchanged (it
mirrors 01-foundation.md exactly and is not the per-column contract this re-scope targets).

## Remaining T6 wiring (not closed by this change)

The pure-JVM engine, the DDL-aligned serializers, and the parity/rebuild proof are implemented and
green offline (full common Maven suite: 426 tests). The Fluss-backed projection writers, the Rust
normalized event emitter / adapter report mapping, and the env-gated gateway Fluss projection
integration remain for the final T6 wiring step; projection remains read-only and never authorizes
a broker command.
