## Summary

Completes **WP-5 (T7)** — the Babysitter's live restore leg — and lands the **WP-6 step-1 credential
re-scope**. The environment-gated MiniCluster + real-Fluss restore integration test now passes:
start -> checkpoint -> restore -> duplicate is a no-op, on a fresh worker. `submit-jobs.sh` was
already wired to wait for a completed Flink checkpoint (`counts.completed > 0`) and fails closed.

## What changed (WP-5 — Babysitter live restore)

- **Product hardening** so a Babysitter can actually restore after a deliberate cancel:
  - `BabysitterJob.buildTopology` now sets `ExternalizedCheckpointRetention.RETAIN_ON_CANCELLATION`
    (mirrors the proven SignalJob idiom). Without it the default retention deletes the completed
    checkpoint on cancel, so a restart silently fell back to a full replay and lost the version gate.
  - Added optional `BABYSITTER_STATE_RECOVERY_PATH` to `BabysitterConfig`; when set,
    `buildTopology` restores from it via `StateRecoveryOptions.SAVEPOINT_PATH` — the same key
    SignalJob uses for state recovery. Previously the Babysitter had no restore path at all.
- **Test-harness fixes** in `BabysitterPositionsRestoreIntegrationTest` (the gate was broken, not
  the product):
  1. `awaitCompletedCheckpoint` required the *same* latest checkpoint across two consecutive 5 s
     polls, which a 2 s-interval job can never satisfy — it now returns the first durably-completed
     `chk-N/_metadata`.
  2. The computed phase-1 restore path was never wired into the phase-2 job — it is now passed as
     `BABYSITTER_STATE_RECOVERY_PATH`, and the retained path is read *after* cancel (so checkpoint
     subsumption cannot delete it out from under the restore).
  3. The zero-action check (`anyActionOrExecutionTable`) scanned the whole shared `default` database,
     so pre-existing action/execution tables from other live runs counted as violations — now scoped
     to tables created during this run (delta vs. an initial snapshot).
- Offline `BabysitterConfigTest` / `BabysitterJobTest` updated for the new constructor arity; both
  stay green and `BabysitterPositionsRestoreIntegrationTest` skips cleanly without the gate env.

## What changed (WP-6 step 1 — credential re-scope)

- Rewrote the commented `executor:` Compose block in `docker-compose.yml` to **drop**
  `ARROW_REST_URL` / `ARROW_APP_ID` / `ARROW_TOKEN` (the T8 contradiction recorded in 19-plan: Rust
  must never hold Arrow creds). It now documents the T4 boundary — the executor talks only to private
  gateway/bridge endpoints on `execution-net` — and stays disabled with `EXECUTION_ENABLED` fail-closed
  `false`. No live route is enabled. (The ingestion service's legitimate Arrow env vars are untouched.)
